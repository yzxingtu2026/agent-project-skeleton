# 动画素材生成

本模块负责将明确的角色、物体或状态动画需求转化为连贯透明帧，并输出可供网页和应用直接使用的单帧序列、spritesheet、循环 WebP 与 manifest。

执行本模块前必须先完整读取 `references/transparent-png-elements.md`，复用其中的纯色背景选择、生成、抠图和质量验证规则。

## 适用范围

- IP 角色待机、呼吸、悬浮、轻跳、眨眼、倾听、思考、回答和结束状态
- 图标、徽章、装饰元素和产品物体的循环动效
- 游戏或网页中的低帧数透明序列动画
- 需要固定帧尺寸、稳定锚点和可重复播放的素材

复杂骨骼动画、长镜头、粒子模拟或需要精确物理运动时，应使用专业动画工具或运行时动画系统，不要强行用少量生成帧替代。

## 输出契约

每组动画至少交付：

- `frames/<name>-000.png` 等等宽等高透明单帧
- `<name>-spritesheet.png`：按播放顺序横向排列的透明 spritesheet
- `<name>-preview.webp`：无限循环的透明动画预览
- `<name>-manifest.json`：前端和工具读取的帧信息
- 原始纯色背景帧网格和统一抠图后的透明帧网格

不要逐帧独立裁切。所有帧必须使用同一个联合内容边界裁切，确保帧尺寸和坐标系一致，避免播放时产生非设计意图的跳动。

## 完整工作流

1. 检查参考图、角色规范、动画用途、目标尺寸、帧数、FPS 和循环方式。
2. 定义逐帧状态表，确保首尾可以连续过渡。
3. 使用 `generate_mockup.py` 一次生成包含全部帧的纯色背景等分网格。
4. 检查每格角色一致性、动作顺序、锚点、边距和背景色。
5. 使用 `remove_solid_background.py` 对整张网格统一抠图；不要逐格使用不同参数。
6. 使用 `build_animation_assets.py` 切帧、统一裁切并生成交付文件。
7. 检查透明 spritesheet、循环 WebP 以及白色、深色和项目实际背景预览。
8. 检查 manifest 中的内容边界和质心变化，确认抖动属于设计动作而不是切帧误差。

## 动画规划

### 默认规格

- 简单循环使用 `6–8` 帧，默认 `8` 帧。
- 默认网格为 `4` 列 `2` 行，按从左到右、从上到下播放。
- 待机动画默认 `8–12 FPS`；动作较慢时可降至 `6–8 FPS`。
- 一次生成一张完整帧网格。只有动作明显超过 8 帧时才拆分多张，并使用上一张已确认帧作为下一张参考。

### 逐帧状态表

生成前必须明确每一帧的变化，包括：

- 主体垂直和水平位移
- 缩放、旋转和形变
- 表情、眼睛和叶片等局部状态
- 波纹、光环和其他关联特效
- 与前一帧的变化幅度
- 最后一帧到第一帧的过渡

循环动画使用周期相位，不要简单复制第一帧作为最后一帧造成额外停顿。8 帧悬浮循环可使用垂直相位 `0, -2, -4, -2, 0, +2, +4, +2`，播放后自然回到 `0`。

## 纯色背景帧网格生成

### 网格约束

- 整张图片只包含一组等分网格，默认 `4×2`。
- 网格边界隐式存在，不生成分隔线、序号、标题或标签。
- 每格使用完全相同的纯色背景。
- 每格中的角色比例、视角、材质、光照方向和水平中心保持一致。
- 每格四周保留安全边距，角色和特效不得越过单元格边界。
- 动作只改变状态表中明确指定的内容，不重新设计角色。

### Prompt 必须包含

- 这是动画序列帧网格，不是角色设定板、UI 页面或多角色展示图。
- 明确列出行列数、播放顺序和每帧状态。
- 所有帧是同一角色、同一镜头、同一比例、同一材质和同一光照。
- 网格没有可见分割线、文字、序号和说明。
- 指定不会出现在角色中的纯色背景，并要求每个单元格背景完全一致。
- 首尾帧能够循环衔接。

启动示例：

```bash
python .agent/skills/ui-mockup-gen/scripts/generate_mockup.py start \
  --prompt "<动画帧网格 Prompt 和逐帧状态表>" \
  --platform asset \
  --reference-image docs/images/ui-generated/character-idle.png \
  --reference-mode auto \
  --size 1536x1024 \
  --text-density minimal \
  --output character-idle-grid-solid-bg.png
```

## 抠图与动画构建

先对整张网格统一抠图：

```bash
python .agent/skills/ui-mockup-gen/scripts/remove_solid_background.py \
  docs/images/ui-generated/character-idle-grid-solid-bg.png \
  --output docs/images/ui-generated/character-idle-grid.png
```

帧网格用于切帧时通常不要加 `--crop`，否则会破坏等分网格尺寸。只有能够记录并恢复原始网格边界时才允许裁切。

构建动画资产：

```bash
python .agent/skills/ui-mockup-gen/scripts/build_animation_assets.py \
  docs/images/ui-generated/character-idle-grid.png \
  --rows 2 \
  --columns 4 \
  --frame-count 8 \
  --fps 10 \
  --name character-idle \
  --output-dir docs/images/ui-generated/character-idle-animation \
  --trim \
  --padding 16
```

常用参数：

- `--rows`、`--columns`：透明网格的行列数，必须能够整除图片尺寸。
- `--frame-count`：实际帧数，默认等于行列乘积。
- `--fps`：播放帧率，默认 `10`。
- `--name`：输出文件名前缀。
- `--output-dir`：输出目录。
- `--trim`：使用所有帧 Alpha 边界的并集统一裁切。
- `--padding`：联合裁切后保留的透明边距，默认 `0`。
- `--preview-format webp|gif|none`：循环预览格式，默认 `webp`。

## 小邻待机循环示例

使用 `xiaolin-idle-ripple.png` 作为参考，生成 8 帧悬浮轻跳循环：

| 帧 | 主体垂直相位 | 叶片 | 波纹 |
|---|---:|---|---|
| 1 | 0 | 自然 | 中等 |
| 2 | -2 | 轻微滞后下压 | 稍扩大 |
| 3 | -4 | 继续下压 | 最宽、稍淡 |
| 4 | -2 | 开始回弹 | 稍扩大 |
| 5 | 0 | 自然 | 中等 |
| 6 | +2 | 轻微上扬 | 稍收缩 |
| 7 | +4 | 上扬最明显 | 最窄、稍强 |
| 8 | +2 | 回到自然 | 稍收缩 |

每格必须同时改变主体和波纹。波纹中心始终位于角色正下方，宽度和透明度随悬浮高度反向变化；不要让角色移动而波纹完全静止。

## 前端使用

- 能直接使用动画图片时优先使用循环 WebP。
- 需要控制播放、暂停、速度或状态机时，读取 manifest 并使用 canvas、PixiJS、Phaser 或项目现有动画运行时绘制 spritesheet。
- 不要在运行时逐张请求单帧；预加载 spritesheet 或 WebP。
- 使用 manifest 的 `frame.width`、`frame.height`、`frames[].x` 和 `frames[].duration_ms`，不要在前端重新推断帧尺寸。
- 页面缩放时保持等比缩放，关闭会造成像素跳动的非整数锚点计算。

## 质量验证

1. 每帧为 RGBA PNG，尺寸完全一致。
2. 每帧主体完整，没有跨越单元格边界或混入相邻帧。
3. 角色身份、颜色、材质、视角和光照在所有帧中一致。
4. 非动画部分保持稳定，只有状态表指定内容发生变化。
5. spritesheet 的帧顺序与逐帧状态表一致。
6. 循环 WebP 从最后一帧回到第一帧时没有明显跳变或停顿。
7. 深浅背景下没有纯色背景残留、彩边或 Alpha 孔洞。
8. manifest 帧数、FPS、尺寸和文件路径与实际文件一致。
9. 动画在目标页面实际显示尺寸下仍然清晰。

## 排障与降级

- 各帧角色漂移：不要逐帧单独生成；强化“同一镜头、比例、材质和锚点”，重新生成整张网格。
- 网格尺寸不能整除：重新生成符合行列比例的图片，或明确裁切到可整除尺寸；不要让脚本猜测边界。
- 某帧为空或主体触边：停止构建并重新生成网格，避免输出不完整动画。
- 波纹等特效被抠除：按透明 PNG 模块调整 `--island-feather`、`--edge-contract`，并重新检查深浅背景。
- 循环接缝跳变：重新规划周期相位；不要用重复首帧伪造循环。
- WebP 不受目标环境支持：使用 spritesheet 和 manifest；仅在明确需要兼容旧环境时输出 GIF。
- 复杂动作无法保持一致：减少动作幅度和帧数，拆分为多个短状态；仍无法满足时改用骨骼动画或人工动画制作。
